# Diagnostics Console

**상태: Experimental.** `Tools > NexUI > Diagnostics Console`.
새 `NEX-*` 진단만 다룹니다 — Studio의 저작 Validation은 여전히 별도 시스템·별도 패널입니다.

## 왜 필요한가

`NexDiagnosticBag`은 **한 번의 컴파일이나 한 번의 화면 로드**에 속하고 그것과 함께 버려집니다.
그 작업이 성공했는지 판단하는 데는 맞지만, 사람이 실제로 갖는 질문에는 답하지 못합니다 —
**"지금 내 프로젝트에 뭐가 잘못돼 있나."**

그리고 Unity Console에만 찍힌 진단은 다른 게 로그를 남기는 순간 사라집니다.

## 무엇이 모이는가

| 출처 | 언제 |
|---|---|
| Compile | `Compile Selected Screen` / `Compile All Screens` — 로그 여부와 무관하게 항상 |
| Publish 실패 | 원자적 교체가 실패했을 때 |

배치 실행은 요약 한 줄만 콘솔에 남기므로, **화면별 상세는 여기 남지 않으면 읽을 수 없습니다.**

## 그룹화 규칙

동일한 진단은 **횟수와 함께 한 줄로** 접힙니다. 200개 노드에서 발동한 규칙은
스크롤할 200줄이 아니라 하나의 문제입니다.

**단, 위치가 키에 포함됩니다.** 같은 규칙이 서로 다른 두 요소에서 실패한 것은 **두 개의 문제**이고,
합치면 하나가 숨습니다.

Bag과 달리 **처음/마지막 발생 시각**도 남깁니다 — *"X 하고 나서부터 이러네"* 가
사람이 원인을 찾는 방식이기 때문입니다.

## 해결됨 표시

`Mark resolved`로 목록에서 감출 수 있습니다. 다만 **같은 진단이 다시 발생하면 자동으로 해제**됩니다 —
돌아왔다는 건 실제로는 해결되지 않았다는 뜻입니다.

## 한계

- **Bounded.** 기본 512개 항목을 넘으면 오래된 것부터 버립니다.
  하루 종일 켜둔 세션이 메모리를 다 쓰면 안 됩니다. 기존 항목의 발생 횟수는 계속 누적됩니다
- Runtime 진단(Command Router·Interaction)은 **자동으로 들어오지 않습니다.**
  각자 인스턴스 소유자에게 보고하는 구조라, 게임 코드가 명시적으로 로그에 넘겨야 합니다
- Studio Validation(`DesignerValidationIssue`)과 통합되지 않음
- SARIF·JUnit Export 없음 (JSON만)
- Timeline 뷰·Auto Fix·"관련 요소 열기" 없음

## 전역 인스턴스에 대하여

`NexDiagnosticSession`은 static이고, **Editor 어셈블리에만** 있습니다.
런타임 어셈블리에는 전역 진단 싱크가 없습니다 — Router·Screen·Interaction이 각자 소유자에게 보고해야
둘이 공존할 수 있고 테스트가 다른 테스트의 진단을 물려받지 않습니다.

콘솔은 본질적으로 **에디터당 하나**이고, 로그 인스턴스를 모든 메뉴와 창에 넘기는 것은
아무것도 사지 못하는 의식(ceremony)입니다.

## JSON Export

버그 리포트 첨부나 CI 읽기용입니다. `JsonUtility`가 아니라 직접 작성했습니다 —
이 타입은 설계상 엔진 비의존이고, 출력 형태는 Unity 직렬화기가 필드를 어떻게 다루는지가 아니라
**읽는 쪽에 안정적**이어야 합니다.
